# 组织方式与设计取舍

## 参考与采用范围

- [Model Architecture Wiki](https://github.com/wxx0912/model-architecture-wiki)：借鉴稳定页面 ID、来源索引、人工导航和确定性查询。模型结构知识仍由关联仓库负责；本仓库表达算法前提，不重建模型识别器。
- [KernelWiki README，b6b4301](https://github.com/mit-han-lab/KernelWiki/blob/b6b4301f15e8ce6955a56776690643ce5db369e6/README.md)：参考来源与综合知识分层、按问题查询、来源版本记录、查询示例和证据边界。这里核对的是该 README 描述的组织方式，不是对其全部工具和数据的审计。

首版采用 Markdown 页面、主题来源表、轻量 Python 标准库查询与校验、从元数据生成的索引。算法原理只维护在正文，标签与别名只服务发现。避免大量 JSON profile 重复正文结论。

暂不采用完整 PR 归档、上游代码镜像、向量检索、数据库、网站框架和版本声明服务。当前规模下，关键目标是让人和 Agent 找到足够小的一组页面，并追溯到原始证据。

## 从问题到候选

```text
问题关键词或算法名 → 检索元数据与正文 → 阅读相关页
→ 核对模型结构、数据、格式与后端条件 → 查原始来源
→ 形成带未知项的实验候选 → 由外部执行与评测工具验证
```

检索结果不等于合法 Recipe。查询程序不代替数学兼容判断，也不自动给出“最佳算法”。

## 四篇样章的设计检验

GPTQ 强调二阶重构与权重更新，SmoothQuant 强调缩放吸收与校准，QuaRot 强调计算图等价和在线变换，OmniQuant 强调固定权重上的有限参数优化。它们不能用一列“量化算法/bit”表达清楚，因此页面共用元数据，正文按实际机制组织。

证据状态放在具体论断旁，不采用一个页面级“已验证”覆盖全部结论。论文设置、当前源码配置与本项目数值实验是三种不同证据；本次知识库建设不运行 GPU 量化实验。
